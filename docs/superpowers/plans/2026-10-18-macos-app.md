# Turnstone Implementation Plan

> **For agentic workers:** Use the execution and parallel-agent skills for independent engines; integrate and review the whole app before completion.

**Goal:** Deliver a runnable offline macOS utility matching the researched conversion and editing workflow.

**Architecture:** A reusable TurnstoneCore target owns the catalog, jobs, output publishing, and conversion engines.
The Turnstone executable owns AppKit drag interception, SwiftUI editors, jobs, settings, and file actions.
Native, media, and document engines have independent source files and share explicit request and execution-context types.

**Tech Stack:** Swift, SwiftPM, SwiftUI, AppKit, PDFKit, Core Image, Vision, AVFoundation, local command-line conversion tools.

**Spec:** ../specs/2026-10-18-macos-design.md

## Global Constraints

- macOS 13 minimum; Swift tools 5.9.
- Source files survive every conversion and edit.
- No upload, account, payment, or hidden network dependency.
- External process arguments are passed directly, without a shell.
- Build in the supplied empty project on codex/initial-macos-app.

## Review Focus

- Filenames containing shell metacharacters remain literal paths.
- Existing output names are never overwritten.
- Cancellation terminates conversion work without deleting successful outputs.
- Incompatible batch selections expose only safe common operations.
- Missing conversion engines produce actionable errors and never false success.
